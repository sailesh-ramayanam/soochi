3rd step is "Coming up with logic"

Logic means step-by-step procedure which explains how to calculate the result for the given input.
This step-by-step procedure is also called as algorithm.

One way to come up with an algorithm is by using the test cases we wrote down previously.
Take a test case.
Write down the input.
Write down the expected result.
Now write down, how you arrived at the result.

Following are some hints.
1. You can strike off on a paper. But how do we do it in a program?
2. What did we do in the above logic? We are simply tallying the characters between the 2 strings.
3. So, it is sufficient to tally the characters.
3.1 Take a character from the 1st string.
3.2 Count how many times it appears in the 1st string. Write it down.
3.3 Repeat this for all the characters in the 1st string.
3.4 Take a character from the 2nd string.
3.5 Count how many times it appears in the 2nd string.
3.6 Check if this count matches with the count in the 1st string.
3.7 If yes, continue and repeat for the next character from the 2nd string.
3.8 If no, then the 2 strings are not anagrams.
3.9 By the time we reach the end of the 2nd string, if there are no mismatches, then the 2 strings are anagrams.

These hints are almost like an algorithm, but one major point is not mentioned in these hints.
How do we store the counts of every character of the 1st string?
This is where our data structure skills come into picture.

There are multiple ways to solve this problem.
Variables approach: Use variables like a_count, b_count, c_count etc. to store the counts.
Arrays approach: Use 2 arrays. In one array store the character, and in the second array store the corresponding count.
Hashmap approach: Use a hashmap to store <character, count> key value pairs.

This method will look like below.
let a_count = 0, b_count = 0, and so on z_count = 0;
for each character c in string {
    if (c === "a") {
        a_count++;
    } else if (c === "b") {
        b_count++;
    } and so on until else if (c === "z") {
        z_count++;
    }
}

There are multiple issues with this approach.

You have to create 26 variables and write 26 if conditions.
But, this is not sufficient.
What about uppercase letters (i.e. A, B, C, ... Z)?
What about digits (i.e. 0, 1, 2, 3 ... 9)?
What about special characters (like @, #, $, %, ;, ', and so on)?
Ww will have to create 100s of variables and write 100s of if conditions. Even if we miss one character, our program will not work correctly.

This is not a wrong approach. But very impractical approach.
